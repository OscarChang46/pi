# BND-L1-001：L1 内部组件

L1 组件通过 Command Port、Repository Port 和 Domain Event Port 协作。首版绑定为进程内强类型调用、本地有界队列和 SQLite 本地事务；不以消息队列拼接聚合事务。

状态变更与其持久事件必须原子提交，提交后才能通知。队列只是可运行提示，Run Store/Event Journal 才是权威来源。FlowEngine 保持无状态；Session 不绑定进程。写命令以稳定 ID 去重，旧 attempt/version/fence 写入拒绝。

同一 Session 的当前活跃 Run 基数固定为 `0..1`。SessionManager 是 `ActiveRunBinding` 的唯一所有者，不保存 `runIds[]`、不维护 Run 队列，也不暴露 `maxRunsPerSession`；历史终态 Run 只由 RunRegistry 留档。Gateway 与 `SubSessionCoordinator` 创建绑定 Session 的 Run 时，必须先经 `SessionRunCommandPort` 以单行 CAS 写 `RESERVED + outbox`，再由 worker 调 RunRegistry；RunRegistry 拒绝缺失或失配的 `SessionRunBindingRef`。

Run 受理 UNKNOWN 时绑定保持占用并查询原命令；终态释放要求 `runId + bindingVersion` 匹配，并经过 `RELEASING` 完成最终 Session 写入。Attempt 的 lease/fence/takeover 仍只归 RunRegistry，同一 Run 接管不会创建第二个 Session 绑定。SM→RunRegistry 使用提交后 outbox，RunRegistry→SM 使用提交后事件/inbox，禁止跨组件同步事务回调。
