# BND-L13-001：L1 Control / PEP ↔ L3 Tool Runtime

## 操作族

Tool Runtime提供可见工具描述与已授权工具执行。当前[L3-FD-2](l3-tool-runtime-detail.md)采用一次有界execute返回ToolOutcome及原操作inspect/cancel；不在L3提供耐久accepted回执或长任务轮询器。注册管理通过ToolRegistry独立管理能力调用，不向L2开放。

## 语义

L34-SPEC-1.0.0接入顺序：L1在PDP前准备不可变ToolTargetV1（原proposal、route、resourceProfileRef、limits、scope、deadline），作为SecurityAction.payload参与targetDigest；取得Permit后以ToolCallRequest.target原样交L3。Guard确认后Host安装绑定完整planDigest的Admission。L1保存ToolOutcome后经Host调用ArtifactBroker.handoff确认引用接管，失败保留L4持有，不重执行。具体字段与确认点唯一见[BND-L34](bnd-l34-001.md)§3—5；该准备过程不下沉L2或L4。

唯一合法动作路径为 `L2 Candidate → L1/PEP → L3 → L4 → L1 Resume → L2`。L2不直连L3，L1不直连L4。L1提供稳定commandId、模型call关联和有效Permit；L3只消费授权结果，Provider DTO不进入公共模型。L3返回ToolOutcome后由L1/宿主保存工具事实再发布业务事件；L3 Promise成功不代表耐久保存。副作用超时可代理查询原操作，无法确认时返回unknown，由上层恢复边界处理，禁止盲重试。结果大小和Artifact限制沿用L3-FD-2。
