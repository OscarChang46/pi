## 跨模块共同约束

| 状态或行为 | 所有者与约束 |
|---|---|
| Session、Run、Attempt | 控制模块分别管理；Session 关联 Run，不代替 Run 状态机 |
| 定义版本与路由 | Registry 拥有不可变定义；Router 仅提案；Run 受理冻结选择 |
| 调度与容量 | Scheduler 决定可运行项，ResourceManager 管理槽；等待审批不占执行槽 |
| 认知与上下文 | 认知接收冻结快照、输出候选；不直接执行工具或修改上下文权威状态 |
| 授权与执行 | 控制协调，Security 裁决，工具守卫检查并消费许可，Execution 执行和清理 |
| 持久事实 | 每个聚合自己的状态与事件原子提交；跨聚合靠幂等协调与恢复，不靠长事务 |
| 未知副作用 | 授权消费成功不等于外部执行成功；不能确认是否发出的调用不得盲目重放 |
| 基础机制 | 存储、时钟、通信、Secret 和进程适配不拥有业务政策 |

统一候选路径为：`认知候选 → 控制协调 → 安全判定 → 工具检查 → 受控执行 → 控制回传 → 认知继续`。现有 Grant 保持真实语义；一次性 Permit、耐久 Journal 和审批恢复是待实施能力。

外部 Run Journal 游标与 Attempt 内部模型事件序号必须区分。连接断开不隐式取消 Run；取消请求受理不代表外部副作用已回滚。必需依赖缺失时装配失败，不返回虚假成功。

## 优先请评审的选择

1. 首版采用单 Host、本地 SQLite、有界并发，先做进程内和 stdio 入口，HTTP/SSE 按需增加。
2. 自定义 Agent 先显式选择不可变版本，再增加确定性的能力路由；不静默替换运行中模型。
3. 先创建 Session，再持久受理 Run；受理回执与最终结果分离。
4. 审批由外部系统拥有业务决策，内核只保留技术挂起、恢复和授权证据；未知副作用进入核对流程。
5. 先完成可恢复的最小闭环，再增加记忆策略、生产 Provider 和更强隔离；本批不补这些算法。

每份草稿末尾均列出局部决策、建议默认及替代方案。可以直接按“文件名 + 决策编号 + 修改意见”反馈；未选择的事项继续保持开放。

## 仍需联合评审的细节

- 安全聚合事件与独立审计收据的先后顺序：两者不能冒充同一事务；需明确各闸门和中断核对点。
- Memory 接受候选时，Permit 消费与 Entry 提交之间的恢复凭据；未收敛前不开共享写入。
- Agent 退役与 Run 受理的并发校验，不能只靠先查后写宣称无竞态。
- Scope 创建意图、Child 注册与关联确认，以及父子预算预留的幂等恢复顺序。

这些是后续契约细化的输入，不以各模块局部操作表代替联合结论。

## 后续实施依赖

先收敛契约和每聚合持久提交，再实现入口、调度和恢复闭环；安全许可与工具执行共同验证后，才启用相应副作用能力。上下文、子 Agent、运维边界可在这些共同契约上分步接入。
