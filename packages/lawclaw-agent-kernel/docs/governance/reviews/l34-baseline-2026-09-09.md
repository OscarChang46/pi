## 发现与处理

1. 旧plan缺完整workload/出口/Secret档案绑定：新增resourceProfileRef及ToolTargetV1，PDP前准备；两侧传播字段，关闭B1规范缺口。
2. 旧JSONL缺握手、关联、帧上限、背压：10种封闭帧、双向seq、请求表及连接状态机已冻结；关闭B3线协议缺口。额外预留第256个ID用于close，避免容量满后无法关闭。
3. 旧查询接口无独立截止、结果损坏可能覆盖已知效果：补queryContext及failed/applied；同步组件、功能域和图。
4. 旧Artifact pin与入口可信性缺可实现交接：冻结Host scoped Admission和ArtifactBroker读/发布/handoff；关闭B2/B4接口缺口。具体存储、停止证明、真实隔离机制仍为运行验收。
5. Schema字符串正则的尾部换行漏洞：采用绝对结尾断言并增加非法Ref向量。

正常轨迹：c1原route/profile→完整目标decide→Guard消费/启动确认→Host绑定planDigest→hello→execute→一次Provider调用→发布Artifact→result→L1保存及handoff。任何准备/Admission失败均无业务派发。

异常轨迹：外部已生效，result前断管→主unknown保留locator→Host查询原操作；执行重试0。取消requested后成功先到仍success/applied；截止先到而首个result迟到时主返回不变，可信观察只交lateFactSink。

扩展轨迹：新增Provider只增加ProviderCodec及能力/证据测试，通过原adapterBinding接入；不改L3工具名分派。新增帧则升级规范版本、Schema、处理表和向量。

备选：只冻结P1可减少传输开发，但无法约束本机supervisor接入；采用P1与P2共享语义和薄编码，既满足当前场景又不引入跨主机协议。总体外部职责不变，手工Draw.io无需改动；边界总览修正L4内部位置及规范标注。
