# 状态仓储、事件 Journal、恢复与 Artifact 草稿

状态：**DRAFT / 待用户评审 / 非规范性**。日期：2026-09-06。

本文提出后续实现选项，不是已经批准的契约，不改变现有 `candidate` 状态或设计基线。
操作名称只表达候选能力；完整 DTO、数据库结构及状态迁移仍待评审后确定。

## 1. 问题与现状

例：Run 已被接受，但进程在通知 Scheduler 前退出。仅有内存队列会丢掉工作；
若工具已经产生副作用，简单重跑又可能重复执行。需要持久事实和可判定的恢复入口。

以下描述本草稿所依据的进程内装配路径；2026-09-08按职责目录重构更新源码链接。它不代表新增的Flow持久化装配也没有Journal或恢复能力。

- [RunRegistry](../../../../../../src/control/run-registry/run-registry.ts) 用 `Map` 保存对象，进程退出即丢失。
- [AgentSystem](../../../../../../src/control/agent-system.ts) 用内存 Session 目录协调 Run，无仓储事务。
- [AgentRun](../../../../../../src/control/run-registry/agent-run.ts) 在对象字段中保存状态、Loop 和结果。
- [Composition Root](../../../../../../src/application/composition-root.ts) 直接装配内存目录，未绑定数据库。
- [框架映射](../../framework-boundaries.md) 明确没有 Journal、事务或未知副作用恢复流程。
- 当前权限快照也在内存；这不等于存在持久 Permit、Approval 或 Memory 聚合。

设计依据：

- [BND-INF-001](../../../../../design/contracts/bnd-inf-001.md)：机制 Adapter 与不透明 Handle。
- [BND-L1-001](../../../../../design/contracts/bnd-l1-001.md)：聚合状态与事件原子提交、提交后通知。
- [StateStorage](../../../../../design/layers/infrastructure-plane/components/state-storage.md)：SQLite WAL、CAS 与恢复游标。
- [ArtifactStorage](../../../../../design/layers/infrastructure-plane/components/artifact-storage.md)：临时写入与原子发布。
- [Local-first](../../../../../design/deployment/local-first-profile.md)：单 Host 本地绑定。

## 2. 职责与权威所有权

默认首版单 Host、单 Worker 进程（进程内可配置有界并发槽）、本地 SQLite WAL、本地 Artifact 目录。
SQLite 库及连接类型只存在于基础设施 Adapter，不进入公开 Kernel 契约。

| 所有者 | 拥有 | 不拥有 |
|---|---|---|
| control | Session、Run/Attempt/Step 的合法迁移与恢复决定 | SQL、文件句柄、数据库锁 |
| tools / security / Memory Domain | 各自 ToolCall、Permit/Approval、Memory 状态规则 | Run 聚合事务与调度 |
| Repository Adapter | 事务、CAS、幂等收据、作用域绑定、持久事件顺序 | 业务授权、迁移合法性、重试策略 |
| Journal Reader | 已提交事件读取和技术消费游标 | 把投递成功解释为领域完成 |
| Artifact Adapter | 内容摘要、发布、完整性及回收机制 | 内容业务解释、授权策略 |

每个聚合与其事件独立提交，即使共用同一 SQLite 文件也不合成跨聚合大事务。
Session 只关联 Run，不内嵌 Run/Runtime；Memory 不存进 Run 聚合；审计不是 Run Journal。
跨聚合由已提交事件和稳定引用协作，暂时不一致由所属应用服务收敛。
Repository 由消费者定义窄 Port；禁止建立接受任意表名或任意领域对象的万能仓储接口。
Host 预绑定不透明分区 Handle；查询不可退回全库搜索或用调用参数切换分区。

## 3. 候选操作表

| 操作族 | 边界 | 输入与输出语义 | 失败语义 |
|---|---|---|---|
| 读取聚合快照 | BND-INF-001 | 绑定分区、稳定 ID → 不可变状态及版本 | 不存在与不可用区分；跨分区拒绝 |
| 提交聚合变更 | BND-INF-001 / BND-L1-001 | 稳定命令 ID、预期版本、领域已验证的新状态与事件 → 提交收据 | CAS 冲突不写入；未知提交结果需查询 |
| 查询命令收据 | BND-INF-001 | 原命令 ID 与语义摘要 → 已提交结果或未发现 | 同 ID 不同语义冲突，不能覆盖 |
| 分页读取事件 | BND-INF-001 / BND-L1-001 | 聚合/订阅范围、游标与上限 → 已提交事件和后继游标 | 过期游标显式失败，不静默跳段 |
| 保存消费进度 | BND-INF-001 | 消费者 ID、预期游标、新游标 → 新版本 | 旧游标写入拒绝，不影响原事件 |
| 扫描恢复候选 | BND-INF-001 | 固定范围、扫描游标、页大小 → 快照引用 | 返回事实；不自行启动或判定可重试 |
| 发布 Artifact | BND-INF-001 | 有界字节流、作用域、媒体类型、大小上限 → 不透明引用及摘要 | 校验/持久化失败不发布引用 |
| 读取 Artifact | BND-INF-001 | 已验证访问范围、引用、有界读取要求 → 只读流 | 缺失、失配、越界均显式失败 |
| 标记与回收 Artifact | BND-INF-001 | 所有者释放引用、扫描批次 → 回收结果 | 引用状态不确定时保留，不猜测可删 |

接口文档需分别说明调用方、所有权、取消、幂等性及错误分类。
错误只暴露稳定原因码与脱敏引用，不携带 SQL、正文或物理路径。

## 4. 写入、通知与幂等流程

1. 入口形成稳定命令 ID；重试沿用 ID，不重新生成。
2. 应用服务读取聚合版本并决定合法变更；基础设施不判断状态机。
3. Adapter 在一个短事务中检查作用域、收据、版本及适用的 attempt/fence。
4. 原子写入该聚合的新状态、事件与命令收据，再提交。
5. 提交成功后发送本地通知或队列提示；通知失败不回滚已提交状态。
6. 消费者从 Journal 拉取权威内容，以事件 ID 去重；队列载荷不当作快照。

相同命令 ID、相同语义返回原收据；不同语义返回冲突。
每个聚合的事件序号严格递增；全局扫描游标仅用于补拉，不承诺跨聚合因果全序。
Host 对外暴露的 Run Journal 游标不能复用 Attempt 内模型流事件序号；两者必须显式区分。
重复事件投递允许发生；接收方处理必须幂等，不宣称 exactly-once 传输。
消费者先持久化自己的处理效果，再推进游标；跨仓储的窗口靠命令去重收敛。
写请求取消若发生在提交之后，不能描述为“操作未发生”；返回未知时查询原收据。
在控制层决定是否派发之前，必须确定接受命令已提交。

## 5. 启动恢复与未知副作用

启动先取得单 Host 数据目录的独占运行权，再检查数据库版本、可读写性与恢复扫描能力。
恢复只读扫描进行分页和限时处理；进入调度的决定仍属于 control。
数据库中的记录是事实来源，内存队列和旧进程资源 Handle 不恢复为有效资源。

| 中断位置 | 读取到的事实 | 所属模块后续行为 |
|---|---|---|
| 提交前退出 | 无收据、无新状态 | 调用方可按原命令重新提交 |
| 提交后通知前退出 | 已接受状态与事件 | control 重建可运行提示 |
| 认知处理中退出 | 中断 Attempt、可用检查点信息 | control 判断安全检查点与预算后新建 Attempt |
| 工具发出前已中断 | ToolCall 阶段与未开始的执行证据 | tools/security 重新验证授权后决定是否继续 |
| 工具已发出但无结果 | 可能存在未知副作用 | 保留 UNKNOWN_SIDE_EFFECT，不自动重放 |
| 结果已持久化而回传丢失 | 结果引用与提交收据 | 从权威结果补回传，避免再次执行 |

首次版本不强制分布式 Lease；预期版本和 Attempt 关联仍需验证。
若未来允许 Worker 接管，fence 校验必须在每次权威写入生效后才能启用接管。
检查点包含哪些冻结输入、结果引用和恢复资格由 control/cognitive 设计决定。
仓储不序列化 Pi SDK 对象或运行中的 Promise，也不从 Trace 重建状态。
外部效果无法查询或幂等证明时，由所属领域暴露人工处理状态；基础设施不猜测成功。

## 6. Artifact 发布与回收

先在受控目录写临时对象，再校验大小与摘要、完成耐久发布，最后返回引用。
引用只包含逻辑标识及必要完整性信息，不包含绝对路径、凭据或可绕过鉴权的 URL。
数据库与文件系统不假装具备共同事务：先发布不可变文件，再提交引用它的聚合。
引用提交失败产生孤立对象，由有界清理扫描回收；不能返回指向尚未发布文件的成功结果。
采用待关联标记与宽限期保护刚发布对象；回收和新引用注册需协调，防止检查后误删。
跨分区引用禁止；物理内容去重即使存在，也不扩大读取授权范围。
读取时校验作用域、发布状态、摘要及大小，采用有界流并支持取消。
清理只消费所有者给出的释放事实，不能用“最近未读”推测领域已不再使用。
摘要不匹配、根目录替换、路径穿越和符号链接逃逸均拒绝并报告稳定原因码。
诊断 Artifact 只容纳已脱敏材料；Artifact 不是日志保存秘密或原始请求的后门。

## 7. 并发、容量与失败

- 同一聚合用 CAS 防止丢失更新；冲突后上层重新读取，不能无条件覆盖。
- 事务不包含模型调用、工具执行或文件流写入，避免占用数据库锁。
- 所有数据库等待、扫描页、事件批次和 Artifact 写入都有配置上限与 deadline。
- 磁盘满、数据库损坏或迁移失败时关闭写入受理；不能回退内存并宣称耐久成功。
- 锁繁忙采用有界机制重试，超出预算返回可重试失败；不得无限等待。
- 配额将满时先拒绝新写入；默认不自动删领域 Journal、命令收据或安全审计。
- Journal/收据保留期限必须覆盖允许重放的窗口；首版不压缩权威历史。
- 关闭先停止受理和派发，再限时完成事务、关闭连接；未确认执行留给恢复判定。
- 备份必须提供数据库与引用 Artifact 的一致集合；仅复制数据库文件不足以保证可恢复。
- Schema 迁移默认停机、显式版本检查并先生成可恢复备份；不自动降级旧 Schema。

## 8. 验收场景

1. 在状态写入、事件写入和提交之间注入故障，不能出现半个已提交聚合变更。
2. 提交后丢通知，重启扫描仍找到 Run；反复通知不重复受理同一命令。
3. 相同 ID 不同载荷被拒绝；CAS 与旧 Attempt 写入无法覆盖新状态。
4. 断线后查询收据能区分已提交和未发现；接口不把未知结果当作失败后安全重跑。
5. 消费者处理后游标提交前崩溃，重放不重复产生领域效果。
6. 工具结果未知时恢复不会再次调用 Provider；已有结果仅回传引用。
7. Artifact 写一半退出、发布后引用失败、回收与注册并发，均无悬挂成功引用或误删。
8. 越分区、摘要失配、路径逃逸、磁盘满与数据库损坏均显式失败。
9. 有界扫描与队列饱和不会无限占用内存；备份可在空目录恢复并核对引用。

## 10. 实施切片与跨域约束

1. 评审独立 Repository/Journal/Artifact Port，补接口注释、替身和故障矩阵。
2. 实现 SQLite 单聚合原子提交、收据与 CAS，先接入 Run，保持其他聚合独立。
3. 接入 Journal 补拉与控制层启动恢复；此时才改变现有内存运行档案。
4. 实现 Artifact 发布/引用协调/回收，再接入工具大结果与诊断包。
5. 加入备份恢复、容量阈值、停机迁移和崩溃注入验收。

必须与 Scheduler 对齐“候选事实与恢复决定”的分工，与工具执行对齐未知副作用证据，
与 Memory 对齐独立仓储与冻结视图，与 Security 对齐 Permit 消费及安全审计写入点。
本草稿不实现这些模块，也不把跨聚合事务、分布式 Worker 或全量事件溯源作为默认依赖。
