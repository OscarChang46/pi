# 上下文组装器：职责、业务流程与调用场景

## 1. 要解决的问题

用户说“继续审查这份合同，结合刚才的检索结果”，模型需要当前任务、相关对话、合同片段、工具结果和适用记忆。全部塞入会超预算，任意删减又可能丢掉任务约束或工具调用关系。

ContextEngine 的职责是：**针对一次模型调用，从确定版本且有权读取的信息中，选择足够完成当前步骤的内容，生成有界、可追踪、不可变的 ContextFrame。**

一次 Run 可以有多次模型调用，每次调用有自己的 Frame。Session 保存跨 Run 的历史事实；Run 转录保存当前执行已提交的事实；Memory 保存长期知识；Frame 是这些来源的一次投影。

## 2. 职责与边界

| 职责 | 具体行为 | 交付结果 |
|---|---|---|
| 绑定组装依据 | 固定 Session 版本、Run 转录头、任务与策略版本、模型预算、授权范围 | 可重建的输入绑定 |
| 收集来源 | 通过查询端口读取历史、已授权记忆与文件片段；限制数量、字节与耗时 | 带来源、版本和必选标记的候选项 |
| 保持语义结构 | 区分可信指令与外部资料，按来源去重，校验工具调用和结果对应关系 | 结构有效的候选单元 |
| 选择与预算 | 保护强制约束和当前任务；按完整轮次选历史，按稳定顺序选记忆和补充资料 | 满足容量的内容集合 |
| 格式化与冻结 | 按固定格式生成规范消息，复核完整载荷预算与来源授权，生成独立不可变值 | Frame 与受控内容引用 |
| 解释组装结果 | 记录采用、裁剪、来源缺席及失败原因 | ReductionTrace 与降级信息 |

职责边界：

| 相邻组件 | 它负责什么 | 与 ContextEngine 如何协作 |
|---|---|---|
| Host / 业务应用 | 定义用户目标、业务资料范围、可信配置 | 经 Run 受理入口提供目标与资料引用，不允许普通请求自设系统约束 |
| Flow 控制协调路径 | 读取运行状态、准备组装请求、提交决定、派发模型调用 | 调用 ContextPort；接收组装失败并交给流程核心决策 |
| FlowEngine Core | 纯计算下一步推进决定 | 消费 Frame 引用或 contextFailure，不自行访问历史、记忆或模型 |
| SessionManager | 保存、追加、分支和归档历史 | 返回固定版本快照；ContextEngine 不改写历史 |
| RunRegistry / 转录存储 | 当前 Run 已提交消息、工具观察及执行状态 | 提供指定转录头之前的事实，不把未提交流式片段作为历史 |
| MemoryManager | 授权检索、版本管理、记忆候选采纳 | 返回只读 MemoryView；ContextEngine 不直接写入或重新实现记忆检索索引 |
| Artifact 能力 | 存取文件、结果与生成的 Frame/Trace 内容 | 按授权读取和发布引用；引用本身不代表授权 |
| 安全域 | 决定并执行访问约束 | 读取、冻结和派发节点复核授权；ContextEngine 不解释业务角色 |
| L2 Runtime / Adapter | 消费规范输入、映射 Provider 格式、调用模型 | 不维护另一套可变会话历史或静默追加未计入预算的资料 |

ContextEngine 对业务事实只读；保存 Frame/Trace 派生产物不等于拥有 Session 或 Memory。首版采用进程内组件，无独立服务部署要求。

## 3. 外部调用场景

“外部”首先指组件外部。业务 API 默认通过 Run 控制路径间接使用组装器，不另设公网组装接口。

| 场景 | 触发者与直接调用者 | 组装内容与时点 | 关键结果 |
|---|---|---|---|
| 首次任务 | 用户/API 受理 Run → 控制协调路径 | 系统约束、目标、明确提供的材料及允许的记忆 | 第一帧；必选材料不存在则不调用模型 |
| 同会话继续提问 | 新 Run → 控制协调路径 | 绑定已确认 Session 版本，加新目标 | 包含已提交历史，不偷偷读取之后出现的新版本 |
| 工具结果返回后继续 | 工具完成事件 → 控制协调路径 | 保留 assistant 的工具调用及对应结果，再生成下一帧 | 不产生只有结果、没有调用的历史 |
| 多工具仍有待完成项 | 工具部分返回 → 流程控制 | 按当前流程等待其余结果；不把不完整单元伪装成完整轮次 | 当前首版不因单个结果到达就提前调用模型 |
| 大文件或检索结果进入 | 业务提供 Artifact，或工具读取完成 → 控制协调路径 | 有界读取指定片段，保留来源引用；外部检索由工具/来源能力完成 | 不自动遍历整个工作区或联网搜索 |
| 子任务启动 | SubagentCoordinator 完成受理 → Child 的控制协调路径 | 子目标、允许继承的父快照、收窄后的资料和工具范围 | Child 独立 Frame，不共享父可变历史 |
| 子任务结果汇合 | Join 已确认 → Parent 控制协调路径 | 将有来源的 Child 结果作为观察加入父转录，再组装 | 子结果不自动成为长期记忆或系统指令 |
| 进程恢复/挂起恢复 | 恢复协调路径 | 从固定版本和已提交转录重建，或校验后复用已保存 Frame | 恢复组装不等于批准重新执行模型或工具 |
| 预算不足 | 当前组装过程 | 按同一策略裁剪可选完整单元，再做最终估算 | 必选内容仍放不下则返回容量失败 |
| 模型或授权变化 | 控制路径显式处理变化 | 原 Frame 不满足新窗口或授权时失效；仅在流程允许重新绑定后组装 | 不自动切模型、放宽授权或更新旧 Run 绑定 |

可选扩展：开发调试的只读预览可以复用同一组装用例，但需单独定义访问范围、返回脱敏策略及是否允许发布派生 Artifact。首版不新增预览接口。

## 4. 业务主流程

1. **确定是否需要模型输入。** 控制路径先确认当前步骤可推进、没有待核对工具执行、没有取消或到期；创建带固定版本的组装请求。
2. **校验请求。** 检查可信作用域、来源引用、预算和格式/估算器版本。非法输入在读取正文前拒绝。
3. **收集固定来源。** 读取指定 Session 快照及 Run 转录；按 sourceSpec 请求 MemoryView，按需读取 Artifact。读取有数量、字节和时间上限。
4. **整理候选单元。** 合并两处重叠的同源事件，按稳定事件引用去重，不能仅按文本相同去重；建立完整历史轮次及工具调用—结果关系；保留来源和不可信内容边界。
5. **放入必选内容。** 系统约束、当前用户任务、当前因果链和显式必选资料先占预算。必选不能由普通相关性排序降为可选。
6. **填充可选内容。** 优先选择最近完整历史轮次，再按冻结相关性顺序选择 Memory 和补充资料。历史按新近程度选择，但输出保持原先时间和因果顺序。
7. **执行确定性归约。** 超预算时丢弃低优先级可选单元；工具调用及结果按因果单元一起取舍。首版不触发新的模型摘要；已有摘要只在来源覆盖与适用版本可验证时采用。
8. **检查最终载荷。** 格式化后重新估算：完整模型输入（含工具定义、消息包装及协议开销）+输出预留不得超过模型窗口；输入还受 Run token 和 byte 限额约束。不能只计算正文。
9. **复核并冻结。** 核对返回来源确为请求绑定版本，复核当前授权；生成 Frame、Trace，发布受控 Artifact。Session 后来变新不要求旧快照跟着升级。
10. **返回组装结果。** 控制路径将回执交给流程核心，按决定完成提交后派发。派发前仍复核取消和授权，避免冻结后撤销的旧输入被发送。

具体例子：用户要求“比较两份合同的违约责任”，某工具一次返回两个条款片段。下一帧保留目标、工具调用和两个结果；预算不足时先删无关旧轮次。若目标要求逐字比对而两个必选片段仍装不下，返回容量失败，由上层明确拆分任务，不能悄悄截掉第二份合同。

## 5. 输入输出语义

使用现有 CD-1 `assemble(ContextRequest) -> AssemblyReceipt` 候选契约，不在本文复制另一套 DTO。

输入必须回答：为哪个 Run 版本组装、绑定哪个 Session 版本与转录头、采用哪些来源、每个来源是否必需、使用哪个授权范围与配置、模型窗口和输出预留是多少。

输出必须回答：这一帧是什么、内容在哪里、依据哪些固定版本、估算占用多少、哪些信息被选中或舍弃、是否发生允许的降级。

成功确认点是 Frame 与 Trace 的引用可读取且绑定校验通过；它不表示模型已经调用，也不表示 Session 已追加。组装失败不返回可派发的半成品。

## 6. 内部组织与扩展点

| 内部职责 | 规则与扩展方式 |
|---|---|
| SourceCollector | 按来源类型注册读取处理器；新增来源复用版本、授权和容量约束，无须在中央增加业务场景分支 |
| CausalSelector | 依据消息关系生成不可拆分单元，按事件身份去重；不按渲染后的字符串推测工具关联 |
| BudgetReducer | 可注入有版本的排序/归约策略；强制保护规则不可被策略覆盖 |
| ContextEstimatorPort | 按冻结模型/估算器版本提供估算；Provider 私有类型留在适配实现 |
| FrameFreezer | 固定格式生成、完整载荷复核、来源绑定、不可变复制与 Trace；随机 frameId 不参与内容等价比较 |

这些是内部职责，不要求各建一个类或服务。新增合同资料源，应注册来源读取器并输出通用候选项；不能让组装器出现“合同审查/文书起草/案件检索”中央业务分派。

## 7. 异常、恢复与验收

| 风险 | 处理 | 应验证的结果 |
|---|---|---|
| 必选内容超预算 | 容量失败交控制流程 | 模型调用为零，必选未被静默删减 |
| 可选 Memory 不可用 | 仅明确允许降级时省略并记录 unavailable | 不使用旧授权缓存；回执显示降级 |
| 必选 Memory/Artifact 缺失 | 来源失败，不伪造空数据 | 无可派发 Frame |
| 未授权或冻结前撤销 | 失败关闭；可选标记不能把越权错误变成普通可用性降级 | 旧内容不返回、不进入模型 |
| 并发历史更新 | 保持请求绑定的旧快照 | 不混用 Session@7 与 Session@8 |
| 缓存误复用 | 比较来源、转录头、授权、策略、格式、模型及估算器版本 | 任一相关绑定变化即不可复用 |
| 读到一半取消/到期 | 停止后续读取，不发布成功回执 | 不产生新的模型调用 |
| Artifact 已写但回执丢失 | 查询或重建派生结果，未引用对象交存储清理 | 不修改业务历史，不重发执行动作 |
| 同源事件被重复提供 | 按稳定来源事件身份去重 | 同一事件出现一次；相同文本的不同事件保留 |
| 估算与实际模型窗口不一致 | 显式报告 Adapter 容量拒绝，校准估算规则 | 不宣称字符估算等于真实 token 保证 |

同一完整冻结输入应产生等价消息、选择顺序和 Trace；允许 frameId 不同。可选来源降级集合不同意味着输入证据不同，恢复时不能宣称两帧等价。

普通日志只放版本、受控引用、数量和原因码；Prompt 与 Memory 正文保存在受控 Artifact，避免进入普通遥测。
