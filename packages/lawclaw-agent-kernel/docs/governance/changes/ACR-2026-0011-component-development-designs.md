## 问题与范围

清单38项中除FlowEngine外37项只有概要，包含组件、内部职责、契约门面和机制适配器。直接为37项各建独立模块会导致重复职责。详见[必要性审查](../../design/reviews/components-2026-09-07/scope.md)。

按用户范围修订，仅对L1/L2/L3/Security的23项设计：16独立组件、3内部职责、4契约门面。Infrastructure/Operations/L4的14项排除实现设计，只把Kernel必要依赖要求放对应目录。保留原组件ID、Port与架构层，内部职责合并交付不代表删除能力或移动层级。字段放在[CD-1契约](../../design/contracts/component-development-contracts-v1.md)，流程和测试放所属组件文档。

## 方案比较

| 方案 | 好处 | 成本/结论 |
|---|---|---|
| 每页独立实现 | 文档到模块表面一一对应 | 重复队列/状态/入口，无独立生命周期的门面被过度建设；不采用 |
| 按责任与生命周期分组 | 保留必要边界，减少重复模块；机制仍可替换 | 需要明确内部职责与接口归属；本轮建议 |
| 只设计主成功Flow | 文档少，短期开发快 | 事务恢复、安全失败、资源清理仍需开发者猜测，不满足待开发标准 |

## 影响与候选决策

- FlowEngine唯一决定ReAct迁移；Host装配Coordinator提交/派发；L2执行单个已提交模型步骤。公共模型边界仍为AgentAdapterPort。
- RunRegistry拥有Run创建和T1/T2/claim；Scheduler只有调度，Child通过同调度链，不能另设状态权威。
- ResourceManager负责准入，ExecutionCapacity实现唯一信号量；LoggingTracingMetrics作为TelemetryPipeline内部Sink。
- Permit消费与首次启动分开；首版本地安全启动授权读取当前Run取消/claim与安全状态，外部I/O不加入事务。
- 本轮设计按FE-CON-1首版关闭模型/工具自动执行重试。UNKNOWN只查询/核对，取消后事实不伪装成回滚。
- 组件字段、错误、状态与保留策略具体化，尚非公开Schema或数据库迁移。候选设计不反向宣称当前代码已满足。

上层约束：UP-AGT-002/003/006/007、UP-CTX-003、UP-TOOL-001、UP-DEL-001、UP-DAT-001、UP-SEC-001、UP-RES-001、UP-OBS-001、UP-INF-001/002、UP-DEP-001/002/003分别由入口/Adapter、调度/恢复、Memory、Guard、Scope、T1/T2、授权、容量、审计、Scoped机制及装配隔离落实。
