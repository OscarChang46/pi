## G0/G1：问题与影响

用户担心控制小随机 I/O、大型黑板正文、KV Cache 卸载互相干扰，且读写放大后期难以修复。当前实现是 SQLite WAL；工作区源码已发现全历史控制查询、完整快照/回执写入以及 Artifact 全文回读校验路径，尚未运行性能测量。

影响 LoggingTracingMetrics、TelemetryPipeline、StateStorage、ArtifactStorage 的计量；FlowJournal/业务 Repository 调用方提供逻辑操作口径。沿现有 BND-INF-001 与 BND-OPS-001，不新增 Kernel 黑板聚合、存储监控服务或 KV 调度器。总体外部职责不变，手工 Draw.io 无需变更。

后续优化可能影响 FlowJournal 投影、Artifact range/stream、跨存储发布/GC 和配置 Schema；本轮只分析，不改这些契约。KV 仅作为 AgentAdapter 下方提供方的可选观测能力。来源、上下层追踪、SFMEA 与计量限制在正文 §2、§10、§11。

## G2：方案与取舍

| 方案 | 收益 | 局限/决定 |
|---|---|---|
| 仅数据库与主机监控 | 接入较少，无业务接口变化 | 看不到有效增量、全量重写、重复读取及 Context 浪费；保留为不扩权替代，但不足以满足本任务 |
| 逻辑操作、Adapter、引擎/设备三层计量 | 区分表示/重试/引擎成本，绑定控制尾延迟与恢复关键路径 | 推荐；需固定字节口径、能力与窗口，不能伪造物理归因 |
| 立即更换数据库并全量对象化/KV 卸载 | 可能隔离大值 | 没有当前基线且引入迁移/GC/推理能力依赖；留待证据驱动的后续阶段 |

计量组件使用静态操作描述器和注册的后端采集器扩展，不在业务 Core 中按存储品牌分派。普通遥测有界旁路，审计保留耐久语义；告警不能直接修改领域状态。候选性能预算与实验矩阵在正文 §8/10；所有数字均未实测。

## 迁移与回退

P0 只加探针，可由装配开关回退且不改变数据库。P1 数据变更需单独确认读写版本、旧日志恢复、对象保护、迁移副本及不可直接回退的情况。禁止降低 FULL/审计耐久性或移除回放记录来获得性能收益。当前两个 SQLite 物理库名保留。
