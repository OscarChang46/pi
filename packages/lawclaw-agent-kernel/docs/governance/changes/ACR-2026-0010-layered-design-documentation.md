## 1. 触发原因与目标

现有设计文档按主题横向拼装，单个文件同时描述 C4 层、领域聚合、多个组件、跨层契约、部署机制和测试，形成重复权威来源。典型问题包括 L1 调度与 L2 Runtime 混写、PDP 与 PEP 混写、L3 Tool Runtime 与 L4 Sandbox 混写，以及 Operations 与 Infrastructure 混写。

本变更建立“总设计 → C4 层设计 → 层内组件设计”的三级结构，并把契约、部署、领域参考和验证材料作为正交维度管理。

## 2. 明确不做

- 不修改运行代码、公共 Schema、数据库或部署产物。
- 不批准 ACR-2026-0009 的系统职责候选结论。
- 不把最终接口签名和 DTO 从评审步骤二提前冻结。
- 不修改人工评审中的 Draw.io 文件。

## 3. 文档权威性

| 层级 | 唯一权威内容 | 禁止内容 |
|---|---|---|
| 总设计 | 系统职责、C4 层边界、全局依赖和不变量 | 组件算法、完整接口签名、具体 Adapter 实现 |
| 层设计 | 层职责、组件清单、允许依赖、控制流、数据流和故障隔离 | 完整 DTO、数据库或中间件实现细节 |
| 组件设计 | 组件状态、算法、生命周期、并发恢复和 Port 使用 | 复制跨层契约、定义其他组件权威状态 |
| 契约 | Port、DTO、错误、幂等、超时、重试和兼容语义 | 组件内部算法和数据所有权 |
| 部署 | Local-first 档案、Composition Root 和 Adapter 装配 | 改写领域语义 |
| 验证 | SFMEA、测试场景和验收证据 | 成为设计权威来源 |

## 4. 目标结构

候选设计包含七个层级：L1 Control、L2 Cognitive、Security Plane、L3 Tool Runtime、L4 Execution Runtime、Operations Plane 和 Infrastructure Plane。每层有且只有一份层设计，每个正式 C4 组件有且只有一份组件设计。

文档清单统一记录 `doc_id`、层级、父文档、权威范围、接口、图和替代关系。旧混合文档迁入治理归档，不参与候选规范扫描。

## 5. 语义收敛

文档迁移同步记录 ACR-2026-0009 下的候选边界：

- L2 通过 Runtime Event 把动作候选交回 L1，不直连 L3。
- L1 PEP 请求 PDP 决策；L3 Execution Guard 只校验并消费 Permit。
- 身份 Token 在 Backend/KernelHost 终止，Kernel 只消费可信 ExecutionEnvelopeRef。
- AgentAdapterPort 是 Kernel 公共模型适配边界；Provider 调用保持 Adapter 私有。
- L4 定义受控执行语义；Infrastructure 只提供进程、容器、文件和网络机制。
- Kernel 只拥有结构化 Parent/Child Run 生命周期；Multi-agent 业务编排仍在上层。

这些结论仍处于五步评审第一步，不构成代码迁移授权。

## 6. 迁移与回退

迁移采用保留历史的文件移动，并为归档文件增加非规范性声明和后继入口。若三级结构未通过评审，可回退文档提交；活动代码基线不受影响。不得通过同时维护旧、新两套候选规范回退。

## 7. 验证

- 七个层设计唯一且完整。
- C4 组件到组件文档覆盖率为 100%。
- 总设计到层、层到组件的父链全部可达。
- 活动设计不存在旧混合文档引用、重复文档 ID 或孤儿文档。
- 跨层接口只有一个契约来源。
- Markdown、PlantUML、SVG 和职责禁止路径门禁通过。
